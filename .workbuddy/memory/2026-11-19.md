## 行动日历：单击看记录 / 双击切主面板日期

需求：日历里单击某天只切换右侧当日记录（原行为不变）；双击则把「今日行动」主面板切换到那一天。

实现（`forest.js`）
- 新增 `actionViewDay`（未设置=今天）、`renderedToday`（主面板最近渲染时的真实今天）、`calendarLastClick`。
- `updateControls()` 改为 `const today = todayKey(); const day = actionViewDay ?? today; const viewingPast = day !== today;`，`displayedDay` 记录渲染日，跨天检测统一改用 `renderedToday`（原 4 处 `todayKey() !== displayedDay`）。
- 新增 `openActionDay(day)`：设 `actionViewDay`（今天则清空）→ 关闭日历 dialog → `updateControls()` → 若主面板未开则 `showModal()`。
- 双击检测走 click 时间戳（420ms 内同一格），不复用原生 dblclick —— 因为第一次 click 会 `renderActionCalendar()` 重建节点，原生 dblclick 会失效。单击若 `calendarDate === key` 直接 return，避免无意义重渲染。
- 历史视图文案：顶部标签由「今日」变 `formatDate(day)` 绿胶囊（`#action-day-label`，点击回到今天）；「今日还可获得」→「当天还可获得」；完成态「今日行动/已全部完成」→「当天行动」；「本周」→「当周」（顶部 `#action-week-line` 首个子元素、`habitDetailText()` 内 `viewingPast` 判断、日历记录行）。
- 历史视图下禁用行内编辑按钮（`edit.disabled = viewingPast`）；`actionHistory()` 仍按 `today` 统计，「历史最佳」高亮 `is-today` 也改按 today。
- `el.actions` 新增 `close` 监听：关闭面板即回到今天，避免下次打开停在历史日。

配套
- `index.html`：`今日` 改 `#action-day-label` 按钮；`#action-total-copy` 内「今日还可获得」包 `#action-total-label`；日历月历下方加 `.action-calendar-hint`（单击查看当日记录 · 双击在行动面板打开这一天）。
- `forest.css`：`.action-day-label` / `.is-past`（绿胶囊）、`.action-calendar-hint`。

验证：`node --test tests/*.cjs` 6 项通过；桌面 1010 与窄屏 430 截图无溢出（summary scrollWidth==clientWidth 288/288）；CDP 真实鼠标双击切换成功、单击不切面板、>420ms 两次点击不误判。

## 修复：日抛行动（今日限定）过零点后从行动日历消失

现象：11-18 当天创建的「NextToken品鉴（今日限定）」在主面板查看 11-18 时可见（2/3），但「行动日历」选 11-18 只列出 4 项（2/4），缺这一条。

根因：`actionAvailableOn(habit, date, today)` 对日抛行动要求 `onlyOn === date && date === today`，把「查看的那一天」和「真实今天」绑死。日历传的是真实 `todayKey()`，所以过了零点 `onlyOn` 永远不等于 today，日抛行动被过滤掉；而主面板 `renderHabits()` 调用时把 `day` 同时当 date 与 today 传（`actionAvailableOn(habit, day, day)`），所以能看到。

改法（`forest.js`）：拆成两个语义
- `actionScheduledOn(habit, date)` = `!habit.onlyOn || habit.onlyOn === date` —— 这天排没排这项，面板与日历共用。
- `actionAvailableOn(habit, date, today)` = `actionScheduledOn && (!onlyOn || date === today)` —— 这天还能不能勾选（日抛过期即锁定）。
- 日历筛选改用 `actionScheduledOn`；主面板 `renderHabits`、`openActionEditor`、编辑器 input 保存、`applyFinanceLink` 的等价调用一并换成语义更准的 `actionScheduledOn`。
- 日历行文案：不可操作的历史日抛项不再显示「+N 标记完成」，改「当天未完成」。

结果：日历 11-18 列出 5 项（有氧/伊比理财/小健身/守-定/NextToken品鉴），与主面板一致；分母口径仍为「当天列出的行动数」（含周常），主面板 2/3 只算必做，两者口径不同属既有设计。
验证：`node --check forest.js` 通过；抽出两函数跑 7 条断言全 PASS（日抛当日列出/过期不列出/当日可勾/过期锁定、日常与周常历史可补记）；`node scripts/build.mjs` + `build-preview.mjs` 重建 dist。

## 历史日期开放行内编辑（重复频率锁定）

需求：11-18 这类历史日期，铅笔按钮原来是灰的（`edit.disabled = viewingPast`，是上一轮做历史视图时顺手锁的）。存安选择「放开，但锁定重复方式」。

风险点（放开前必须先处理的）
1. `onlyOn = repeat === "once" ? day : undefined` 且 `day = todayKey()` —— 在历史视图里编辑日抛行动会把它搬去今天。
2. `openActionEditor()` 用 `todayKey()` 做 `actionScheduledOn` 校验，过期日抛会静默 return。
3. `saveHabits()` 里 `renderHabits()` 默认今天：历史视图保存后列表会悄悄换成今天，而 `displayedDay` 没变 → 头部日期与列表错位。`refreshSavedForest()` 同样有这问题。

实现（`forest.js`）
- 新增 `actionEditorDay()` = `actionViewDay ?? todayKey()`，作为编辑/新增的基准日。
- `openActionEditor()`：用基准日校验；`lockedRepeat = Boolean(habit) && day !== todayKey()`；历史编辑时标题变「编辑行动 · 11月18日」，`#action-repeat.disabled = lockedRepeat` 并写 title。
- 保存路径：`day = actionEditorDay()`；`onlyOn = repeat === "once" ? (habit.onlyOn ?? day) : undefined` —— 日抛限定日保持原值，只有今天改成/新建日抛才取基准日。
- `updateControls()` 去掉 `edit.disabled = viewingPast`，改为常开，title 提示「历史日期，重复频率已锁定」。
- `saveHabits()` 与 `refreshSavedForest()` 的 `renderHabits()` 都改为 `renderHabits(actionEditorDay())`。
- `forest.css`：`.action-editor-form select:disabled` 纸色底 + `not-allowed`，让锁定像只读而非失效。

验证（headless Chrome + CDP 真机脚本，17/17 通过）
- 注入 6 项行动的存档 → 日历 11-18 与主面板都列 6 项一致；未完成的日抛显示「当天未完成」。
- 双击 11-18 进面板：所有 `.action-edit` 均 `disabled=false`。
- 打开 NextToken 编辑器：标题含「11月18日」、`repeat=once` 且 disabled、cursor=not-allowed。
- 改名触发自动保存：localStorage 里 `onlyOn` 仍为 `2026-11-18`、habits 数量不变、状态「已保存」、面板仍停在 11-18。

遗留：历史视图点「+ 行动」新增时，日抛仍按 `todayKey()` 落日期（标题也不带日期），要不要也跟随基准日，待存安决定。

## 周常行动改为「本周达标才发一次生命力」

问题：周常（如 AI大冒险 每周 4 次）勾一次就立刻弹「生命力 +7」，等于把周常当日常结算。

口径（已与存安确认的方向）：周常打卡只记次数、**不产生生命力**；一周内凑满目标次数后，**一次性发放该项行动的奖励额度**（AI大冒险 = 达标给 7，不是每次 7）。

实现（`forest.js`）
- `addActionEntry()`：weekly 时 `reward = 0`、`collected = true`（只是"不需要领取"）、加 `weeklyMark = true`；随后调用 `awardWeekly()`。
- 新增 `weeklyAwardId(habit, day)` = `${weekStart}:${habit.id}:weekly`、`weeklyAwardEntry()`、`weeklyRewardSettled()`、`awardWeekly()`。达标奖励 entry = `{ reward: habit.reward, collected: false, weekly: true, actionLabel: '名称 · 本周 N 次达标' }`，进门口光球可领取。
- `weeklyDone()` 排除 `entry.weekly`，否则达标奖励会被自己算成第 N+1 次；`dailyActionTotals()` 同样排除，避免日历「已完成 x 项」多算；`dayEnergyTotals()` 跳过 0 分 entry，避免只有周常打卡的日子污染「日均」分母。
- `toggleActionCompletion()`：取消打卡时连带移除本周 `awardWeekly` 记录；奖励已花费则拒绝取消（提示"本周达标奖励的生命力已花费"），扣回额度含奖励部分。
- `updateControls()`：周常行内 reward 始终取 `actionReward(habit)`（打卡 entry reward 为 0，不能取 entry）；未达标时 `.habit-reward` 加 `is-locked`（虚线 + 降饱和 + title「本周 N 次达标后一次性获得 X 点」）。
- 日历行文案：周常显示 `已达标 / 已打卡 / 达标可得 +X` + 当周 n/N，不再写「+7 标记完成」。
- `forest.css`：`.habit-reward.is-locked`。

旧存档兼容：`weeklyRewardSettled()` 把「本周内该行动有 reward>0 且非 weeklyMark 的记录」视为已结算，本周不再补发（避免重复给钱），下周起按新规则。已发出的不追溯回收。

验证：3/4 时 +7 芯片虚化、无光球、pending 0；第 4 次达标 → 芯片解锁 + 光球 +7 + 文案「本周 4 次达标，7 点生命力可在家门口领取」；领取后 balance +7；取消第 4 次 → 奖励撤回、扣回 7、周进度回到 3/4。旧格式 2/4 存档补到 3/4 不发钱、日常行动仍 +1。窄屏 430 与日历均不裁切。`node --test tests/*.cjs` 6 项通过，dist 与离线试玩版已重建。

## 允许补记历史日期（含日抛行动）

现象：11-18 的「NextToken品鉴（今日限定）」昨天漏点，面板里圆圈点不动——按钮看着能点，实际没反应。

根因：`toggleActionCompletion()` 里 `!actionAvailableOn(habit, date, day)` 拦掉；而 `actionAvailableOn` 对日抛要求 `date === today`，所以历史日的日抛永远不可勾。日历侧同理（`button.disabled = !actionable`）。

改法（`forest.js`）
- `actionAvailableOn(habit, date, today)` 改为 `actionScheduledOn(habit, date) && date <= today` —— 只要不是未来日期、且这天确实排了这项行动就能勾/取消，日抛也允许事后补记。
- 日历行文案：`repeat === "once" && calendarDate !== today` 时显示「+N 补记完成」，与当天的「标记完成」区分（原来的「当天未完成」分支已无触发场景，移除）。
- 未来日期仍被 `date <= today` 与格子 `button.disabled = key > today` 双重挡住。

验证（headless Chrome + CDP，16/16 通过）
- 日历：日抛行显示「+2 补记完成」且 `disabled=false`；点击后写入 `2026-11-18:nexttoken`（reward 2）、计数 3/6→4/6、状态「已标记完成，2 点生命力可在家门口领取」；再点可取消。
- 面板：切到 11 月 18 日后计数 2/3→3/3、`aria-pressed=true`、生成 1 个待领取光球、底部提示同步；刷新后记录仍在。
- 未来日期格子仍不可选。

注意：`toggleActionCompletion()` 对「生命力已花费」的记录仍拒绝取消；周常补记仍按「本周达标一次性结算」走。


## 收回旧规则重复发放的周常生命力（需求）

背景：周常改为「本周达标只发一次」后，旧存档里按「每打卡一次发一次」产生的点数（如门口 AI大冒险 的 +7 光球）仍虚高，存安要求收回。

实现（`forest.js`）
- 新增 `reclaimWeeklyBugEnergy(entries, habits, snapshot)`，在 `readState()` 里紧跟 `pruneActionEntries()` 调用，迁移后 `save.write()` 写回，幂等（靠 `weeklyMark`/`weekly` 标记识别是否已处理）。
- 逐周分组旧格式记录（`kind === habit.id && !weeklyMark && !weekly && reward > 0`）：
  - `collected === false`（门口未领的球）→ `reward 0 + collected true`，整颗作废；
  - `collected === true` → `withheldEnergy += remainingEntryEnergy(entry)`，只扣没花掉的部分，**已花费（种树/肥料）不追**；
  - 该周打卡次数 ≥ `weeklyTarget` 且无 award 时，补一条 `collected: true, weekly: true` 的达标记录（`date` 取该周最后一条），保证应得那一份不被误伤。
- `readState` 返回 `weeklyEnergyReclaimed`（收回点数），初始化末尾 `notify()` 提示「已收回 N 点……」，因写回后 amount 归 0，只提示一次。

验证（headless Chrome + CDP）
- 本周 2 条未领（各 7）→ 余额 0、光球消失、提示收回 14。
- 本周 2 条已领（各 7）→ 余额 0、收回 14。
- 本周 4 条达标（共 28）→ 收回 28 后补发 7，余额 7，无新光球。
- 已花 3 点（`spentPlantEnergyIds`）→ 只收 11，余额 0，日常行动 +1 光球不受影响。
- `node --test tests/*.cjs` 6/6 通过；`dist/` 与离线试玩版已重建。
